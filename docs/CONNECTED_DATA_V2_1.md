# S² FieldShift V2.1 — Connected Earthdata architecture

## What is implemented

- `functions/api/power.js`: deployable Cloudflare Pages Function for **live NASA POWER** daily point queries, 7 allowed variables, explicit UTC, provenance URL, missing values, request validation, bounded 1000-day requests, Cloudflare edge caching. Avoid repeated calls and respect NASA fair use.
- `functions/api/catalog.js`: public NASA **CMR granule search** for GPM IMERG Final Daily V07 and SMAP L4 V8; it returns the first page of records for human inspection, **not full raster data**.
- `scripts/sync_earthdata.py`: authenticated monthly historical ingestion of NASA full source granules, geospatial IMERG ROI extraction and closest SMAP grid pixel, per-file SHA256, resumable manifest, explicit missing-date list and completeness test. This is an automated **acquisition program**, not a claim that historical archives have already been acquired.
- `src/ConnectedSources.tsx`: user-controlled source-connected NASA POWER query, live metrics and Earthdata source discovery, integrated into Climate Evidence.
- Bundled V2.0 data remain available offline. **DO NOT overwrite them on failed requests**.

## Sources and exact time semantics

POWER daily point: https://power.larc.nasa.gov/docs/services/api/temporal/daily/
Earthdata CMR: https://cmr.earthdata.nasa.gov/search/
NASA Earthdata Cloud migration (September 2026): https://github.com/nasa/gesdisc-tutorials/blob/main/user-guidance/GES_DISC_Migration_to_Earthdata_Website_and_Earthdata_Cloud.md

## Deploy

Create Cloudflare Pages project with `npm run build`, output directory `dist`, and Functions directory `functions` committed next to source. Vite `npm run preview` does not run Cloudflare Pages Functions. For testing the gateway locally, use `npx wrangler pages dev dist` after building.

## Full-history Earthdata collection

Earthdata registration and Earthdata download authorization are required. Do not commit credentials. On a machine with network access and sufficient disk:

```bash
python -m pip install earthaccess h5py numpy
python scripts/sync_earthdata.py --product imerg --start 2015-01-01 --end 2025-12-31 --output earthdata_archive
python scripts/sync_earthdata.py --product smap --start 2015-04-01 --end 2025-12-31 --output earthdata_archive --cadence daily
```

**Important**: Daily IMERG global files can sum to 100+ GB for eleven years. For SMAP, daily selection deliberately omits most 3-hourly granules. Daily coverage is checked, but **not full temporal 3-hourly coverage**. For all 3-hourly files use `--cadence all`; this is a much larger task and needs a separate completeness audit of expected timestamps.

Processing these datasets needs time, disk and authenticated network. The extraction program does not imply the output is preloaded into the public web app. A production deployment should store compact results in R2 or object storage and expose paginated timeseries via a Cloudflare Worker.

## Other sources and hard limits

- SoilGrids: ISRIC WCS/WebDAV or download; REST service temporarily suspended. No measured plot soil result can be generated by the API.
- FAO GAEZ: modelled potential yields, not actual harvests or rotation-specific effects.
- Senegal DAPSA/ANSD yields: only ingest released records under their access conditions and anonymize. Do not infer causal rotation effects without identification design.

## Claim discipline

No full IMERG/SMAP 2015–2025 dataset is included in this V2.1 release. The NASA POWER gateway can retrieve an arbitrary requested time window (<=1000 days per request) when deployed and online. Any unavailable source returns an error, never a manufactured estimate. Calling this a complete verified agronomic decision platform would be inaccurate until soil tests, crop data and local validation are supplied.

After the authenticated sync, run `python scripts/publish_layers.py --archive earthdata_archive --dest public/data/earthdata_connected.json` then rebuild/deploy. The application reads `earthdata_connected.json` and displays count and missing-date coverage. Avoid committing generated large archives to Git; upload compact/static payload via object storage as the project scales.
